Scale

These numbers guide Atlas design. They are not hard limits. Design so Atlas works well at these sizes and does not break just past them.

Fleet

  • Design for about 20 Assets at most. Larger fleets should still work, but without guarantees.
  • At this scale, IDs that people read or that cross a field link are 1 to 4 letters or digits, such as A1 (the ID rule). That gives over a million IDs and keeps field-link frames short.

Setup

  • A Core runs one site at a time, and each site has exactly one gateway at a time. Different sites, or later radio systems, may use different gateway designs (Environment).
  • In practice, one operator runs Atlas at a time.

Radio

  • Links start with pure LoRa, then move to a multi-layer mesh with FLRC between Assets wherever FLRC is viable (Environment).
  • The telemetry rate is about every 15 seconds on LoRa and about every second on FLRC.
  • Each Fieldlink sets its own size limit and splits records into chunks if it needs to. Protocol records have no size cap and no chunking. About 200 bytes per frame is a goal for slow links, not a limit.
  • Tasks go before telemetry when the radio is busy. Expect a few Tasks or settings changes per minute per Asset.

Runs and storage

  • Each run lasts up to about 2 hours, limited by battery. Core should run all day across many runs.
  • Each Reset ZIP can be up to about 1 GB. Size is not a concern.
  • Core keeps at least the last 30 days of runs before old ones are removed.
