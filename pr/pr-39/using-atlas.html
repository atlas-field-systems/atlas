Using Atlas

An operator uses the Command Interface to watch Assets and request work. Core keeps the shared picture, the requests, and the event log. A gateway carries Atlas across a field link. The Asset app controls its equipment and reports what happened.

Core and Fusion sit inside the inner wall. Plugins sit in the second ring. Everything else sits outside the city and reaches Core only through the Core API. Design decisions has the layout.

Most physical Assets use the gateway path. The gateway and the radio Asset run the same Fieldlink package for their field link. A direct-IP Asset, often a digital one, calls the Core API itself. A site runs one gateway at a time, and the gateway design can change as connectivity evolves. The diagram shows responsibilities, not a required network topology.

The first-flight setup runs the Asset app on a ground Raspberry Pi that calls the Core API directly over IP, with no gateway. A separate SiK equipment link connects that Pi to the ArduPilot vehicle. The app represents the vehicle even though it is not aboard it.

An operation runs without restarts

Core starts before any other part of an operation and stops after all of them. Each start of Core begins a new, empty run, and stopping Core ends it (Runs and identity). Core never restarts during an operation. Gateways and Assets stay running too. Links can drop and reconnect while those processes keep their state, and a refreshed Command Interface recovers from Core's event log.

An Asset whose app stops leaves the operation. Core shows it offline, and the other Assets keep working. An Asset that crashed is taken apart and evaluated before it runs again. An Asset keeps nothing from an earlier run when it starts. This is about the app stopping. A dropped link is not a stop: the app keeps its state and reconnects as the same Asset.

An Asset's settings are its current configuration, kept in its entry.

Information-focused stories

These stories describe intended use.

Locate the tracker

A reporting-only Asset is a Raspberry Pi with a GPS peripheral and an uplink. It obtains its own position and reports telemetry to Core for the operator. It accepts no equipment-control commands. If it loses its GPS fix, Atlas retains its last known position and the reported GPS condition. The tracker does not send the old position as a new fix.

Observe an aircraft

An ADS-B receiver is an Asset. It reports Observations about a passing aircraft. Atlas uses those Observations as evidence to maintain a shared Track of the aircraft for the operator to follow. The operator does not need to control that aircraft to observe it through Atlas.

Research a place

An operator selects a building or area and runs a Plugin action on it. The Plugin returns a list, or creates geo features and stores files as Objects. Every operator sees the call and its result. Plugins has the examples.

Attach a photo to a place

An operator uploads a photo and attaches it to a building's geo feature. Every operator can open it from that place. If it was the wrong building, the operator moves it; if it was the wrong photo, the operator deletes it, and history keeps the record of both.

First flight follows one complete use of these parts.
