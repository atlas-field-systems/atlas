Decision log

The owner's product decisions, newest first. This page is authoritative: when another page disagrees with it, that page is wrong. Each entry names its scope, so a rule is never stretched past it, and the one page that owns the detail.

Only the owner adds or changes an entry. A thread's recommendation is not a decision until the owner makes it. Atlas is still a draft, so any entry may be reversed. A reversal updates this log and, in the same pull request, every page that still teaches the old rule, and adds the old wording to the retired phrases so CI catches it coming back.

Dates are when the owner decided (America/New_York).

Failsafes

Date Decision Scope Home
2026-11-12 While the flight controller's own protection is in control, operators can only watch. The Asset shows that the flight controller took over and refuses operator commands until a person hands control back to Atlas. Flying Assets. Failsafes
2026-11-12 An override with Hold or pause re-arms every failsafe rule, not only lost-contact and low-battery rules, so a held Asset stays protected by everything the operator set up. Failsafe state, after a Hold now or pause override. Failsafes
2026-11-12 Failsafe rules are simpler: each firing runs its response once, with no configurable fallback (the critical Return-to-home fallback stays); priority does not only rise, so a rule can act again once no response is running; and there are no separate missing- or stale-data conditions. Area rules keep their distance margin and time outside. Failsafe rules. Failsafes
2026-11-12 When several critical battery rules match, the highest-priority one wins. If a critical rule's response fails while the battery is still critical, the Asset falls back to Return to home, and that is the only fallback. Nothing is retried. Critical battery rules. Failsafes
2026-11-11 Operators can send a Fail-safe command to an Asset, as they send Land, Return to home, or Hold. The Asset treats it exactly as if its failsafe had fired: it runs the operator's failsafe rule for the command, and only if no rule applies falls back to the maker's built-in safe action. This is the answer to emergency commands for an offline Asset; Land, Return to home, and Hold get no offline exemption. Commands. Failsafes
2026-11-11 When an operator overrides a fired failsafe with Hold or pause, protection is re-armed and can fire again once its condition recurs; which rules are re-armed is the 2026-11-12 entry. A fired failsafe still can't be cancelled. The overrides stay. Failsafe state, after a Hold now or pause override. Failsafes
2026-11-11 A critical battery rule is required on every flying Asset. Core refuses Tasks to a flying Asset that has none. Flying Assets. Failsafes
2026-11-11 A lower critical battery level always fires, even after a Hold or pause override, so a held Asset can't hover until its battery dies. Battery rules, in and out of failsafe state. Failsafes
2026-11-11 Every flying Asset must have its flight controller run its own failsafe, such as returning home, when it loses contact with the computer running the Asset app, independent of Atlas. Flying Assets. Failsafes
2026-11-11 A failsafe response is always protective. There is no "keep going" or continue response: a condition whose response would be to keep going is not a failsafe. Failsafe responses. Failsafes
2026-11-11 During a failsafe the operator may override with Land, Return to home, or Hold sent with now, or with pause. Failsafe state. Failsafes
2026-11-11 A failsafe that has fired can't be cancelled or left; the Asset stays in failsafe state until it shuts down. Failsafe state. Failsafes
2026-11-11 Failsafe boundaries are drawn separately from saved places; a failsafe response can't name a saved place. Failsafe rules. Failsafes
2026-11-11 Up to 16 failsafe rules and 16 pieces of equipment (subsystems) per Asset. Per Asset. Protocol failsafe records
2026-11-10 Any operator may change failsafe rules. Outside failsafe state. Failsafes
2026-11-10 Low battery is a set percentage, not an estimate of the charge needed to get home. Battery rules. Failsafes
2026-11-10 A failsafe rule may react to degraded or faulted equipment. Declared subsystems. Subsystem conditions

Date Decision Scope Home
2026-11-13 Each Asset decides which files it sends, by its configuration and link. A file a Task asks for is sent with that Task; other files are sent when the link allows, such as over Wi-Fi but not LoRa. Operators never fetch an earlier file from an Asset, and Assets never answer operators directly: everything goes through Core. Files from Assets. Asset behavior
2026-11-12 Assets can upload files as Objects. An Asset's file is not pinned to where it was taken automatically: the Asset creates a geo feature alongside it, and the two are linked. Assets and Objects. Core API, Objects
2026-11-11 Deleting an Object hides it from operators for the rest of the run. Core keeps it, marked deleted, in the end-of-run ZIP; it is not destroyed. Objects. Core API, Objects
2026-11-11 Object files are capped at 100 MB by default. An admin may change the limit through the max_object_bytes setting. Object files. Core API, Objects
2026-11-11 Lists returned are capped at 1000 items. Pages of history and Plugin calls, and lists in a Plugin answer. Core API, Plugins answer
2026-11-11 Plugins choose how they appear: help_text, in_menu, and show_on_map, with menu and map off unless set. They should be really easy to configure and describe their own actions. Plugin descriptions. Plugins
2026-11-11 A right-click action appears only when the action has exactly one input of the clicked kind. The map's right-click menu. Plugins in the interface
2026-11-10 A Plugin's rights over geo features are create-only. Plugin-suggested routes and repeating Plugin calls are out of scope. Plugins. Plugins
2026-11-10 Tracks come only from Fusion. Old Observations and Tracks stay in the picture for the whole run; Core adds no stale flag. Within a run. Core API, Entities
