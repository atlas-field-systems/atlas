# Protocol laws

The rules every Atlas record follows. If a change breaks a law, fix the change
or deliberately change the law first.

**Bloat is the enemy, but good organization is not bloat.** Include only needed fields and records, and define nothing twice. For example, listing the same command kinds under two records is bloat. Grouping records into folders is not.

"Checked" means `npm run check` fails when the law is broken.

1. **Protocol defines shared records.** Core, clients, gateways, and Assets build, check, and store the same records, with the same variables, names, units, and shapes. Protocol does not define how programs talk. The [Core API](../../core/docs/api.md) and the Fieldlinks own those rules, including requests, events, delivery, acknowledgements, and credentials. Local configuration and diagnostic logs belong to their components. Protocol does define request bodies in `requests/`, so Core checks a whole request with the one validator. A request may reference an existing geo feature, including a nullable Object attachment. It may carry complete report records in a batch. A request body is not a record: it carries no field Core stamps, such as `time`, `asset_id`, `task_id`, or `requested_by`. *Checked: requests carry no stamped field and allow no extra fields.*
2. **Variables are the building blocks.** Define each field once in `variables/` and reuse it everywhere. Records, kinds, and components only point at variables, components, or records. *Checked.*
3. **No redundancy.** Never put the same fact twice in one record, and never send what the receiver can work out on its own. A record carries other records whole.
4. **Full readable names.** Field names are whole words, such as `altitude_reference`. Protocol defines no short keys and no type numbers. Each Fieldlink chooses its own compact encoding.
5. **Records are grouped like folders.** A record's name is its path under `records/`, joined by dots: `records/task.json` is `task`, and `records/report/status.json` is `report.status`. A record with several kinds requires `kind`, and each kind is its own file `records/<record>/<kind>.json`, named by its `kind` value and unique within its record. Grouped records carry `type`, fixed to their name, so they can travel in mixed batches. Other records carry none. A component with several kinds follows the same pattern: `components/<component>/<kind>.json`. *Checked.*
6. **Flat records with one time.** This law covers records, not request bodies (law 1). Every field sits directly in the record, with no header, wrapper, or envelope. A component groups fields that belong together, such as a `position` or `settings`. Each record has one `time` for the whole record, and a record about one Asset carries `asset_id`, as the Charter's [shared data rules](../../atlas/CHARTER.md#keep-shared-data-simple) require. Records carry no creator counter or creator ID such as `seq` or `from`. Who requested a record is `requested_by` where it matters. *Checked: `time` is required, `asset_id` comes from its variable, and no record has `seq`, `from`, or extra fields.*
7. **Fixed units.** Times use milliseconds since 1970, UTC. Distances use metres, speeds use metres per second, and headings use degrees from true north. Every altitude says what it is measured from. Every uncertainty is a 95% bound: the true value is inside it 95 times out of 100.
8. **Settings are end states.** A setting says what it should be (`lights: on`), never "toggle" or "switch". A setting left out of a record is unchanged.
9. **Limits, not chunking.** Text and lists have length limits, and no field holds a whole file. Records have no size cap and are never split by Protocol; each Fieldlink splits and compresses for its medium. *Checked: text and lists.*
10. **Short IDs.** IDs people read or that cross a field link are 1 to 4 letters or digits, following the [Charter](../../atlas/CHARTER.md#keep-shared-data-simple). Event IDs, such as `request_id`, are integers. A `task_id` is a number from 1 to 9999, because it also gives the order an Asset runs its Tasks in. *Checked: every `*_id` variable.*
11. **Asset reports are fixed.** Every Asset reports the same data the same way, using defined reports and components. Do not add free-form or misc fields. New kinds of data get a new defined report. Assets choose their subsystem identities and labels and declare them in the description, but conditions use [shared meanings](../../asset/docs/status.md). *Checked: the report list names exactly the records under `records/report/`.*
12. **One command kind per action.** Each action is its own command kind even when its fields match another. A payload drop and `move_to` both take a position, but their meaning and success differ. The Asset's `description` declares support per kind, and per setting by name. Shared fields reuse the same definitions. Copter and fixed-wing actions have separate command families. *Checked: the command list names exactly the Task kinds, except `settings`; the setting list names exactly the fields of the `settings` component; a Task request takes exactly the Task record's kinds; a failsafe response takes exactly the command kinds except `failsafe`.*
13. **Assets observe; fusion decides tracks.** Assets report what they observe, never tracks. Tracks come only from Core's fusion, and no caller writes one.
14. **The package version is the only version.** Protocol's published package version is its only version. Definitions and records carry no version field. Programs select definitions through their package dependency, and the Core API and each Fieldlink compare the hash of the definitions ([Changes and releases](../../atlas/design-decisions.md#changes-and-releases)). Published packages never change. *Checked: no field ends in `version`.*
15. **Tools only display.** The CLI and the viewer read everything from `definitions/`, never name a record, and never send anything. *Checked by tests.*
